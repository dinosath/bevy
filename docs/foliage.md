# Foliage: assemblies, voxels, skinning, preserve area

## UE reference [UE-doc: Nanite Foliage & Assemblies pages, UE 5.9 docs; status Experimental]
Three systems: **Assemblies** (parts instanced inside one asset, ≤65k part instances, "a large array of matrices", no nesting, per-assembly part copy; far parts merge into the base mesh), **Voxels** (4×4×4-voxel bricks, ≤128 bricks/cluster, binned + special raster permutation, chosen when voxel error < triangle error), **Skinning** (bone-driven wind; accurate bounds vs WPO's worst-case padding). Animation cut-off at screen size 0.1 by default. Quoted numbers: largest tree 3.5 GB → ~29 MB disk; 36 MB → ~2.7 MB streamed per tree per view; ~500k instances; example tree 41 M triangles / 12 unique parts / 2 160 part instances / 850 bones; 100k bones ≈ 0.1 ms. Voxel properties "likely to change or be removed". **The docs' wind-limitations list and the 5.9 release-note description of Dynamic Wind disagree (local forces/characters); not reconciled.**

## Bevy facts [Bevy]
Meshlets: opaque only, no skinning/morph/vertex animation. Standard path: alpha-tested instanced foliage, `VisibilityRange`, GPU skinning (`skin.rs`), no wind, no assemblies, no impostors, no voxels. `EXT_mesh_gpu_instancing` imports as instances.

## Measured today [Bench] (`docs/open_world/benchmarks.md`)
LOD chain 6.3×, merged-region forest HLOD 3× alone / ≈+2 % over LOD on GPU but visible entities 6 767 → 943, occlusion alone a loss, shadows 22 of 78 ms.

## Design [Proposal]
1. **Assembly = BVH `InstanceGroup` node**: `{part_asset (BVH root), transforms_range in a transform array, count ≤ 65535}`. During cluster-group traversal a group thread expands `count` part instances lazily: for each transform, test the part's bounds (frustum/HZB/error) *before* pushing to the candidate queue. Far assemblies terminate at a **merged base-mesh LOD** (offline simplification of the whole assembly, like UE's "merge into base mesh"). Memory: part geometry once + 48 B per transform. Cost: a culling-time loop over transforms (UE concedes "a small performance trade-off during cluster culling").
2. **Far representation — decide by experiment, not by imitating voxels.** Candidates: (a) aggregate merged proxy meshes (have: `bevy_world_streaming::hlod`, measured), (b) octahedral impostors (not built), (c) 4³ voxel bricks. Protocol: same forest, fixed camera paths, measure frame time P50/P95/P99, VRAM, visual error vs LOD0 (per-pixel luminance difference), shimmer under motion (temporal diff). Choose by Pareto; **voxels are research-required and not started.**
3. **Preserve Area experiment** (tooling): for thin geometry (leaf quads, blades, needles, ribbons) measure *projected area ratio* `A_lod/A_lod0` per LOD level from the baked `MeshletMesh`; today's simplifier (`SimplifyOptions::Sparse | ErrorAbsolute`, attribute-aware, locked borders) is expected to shrink open sheets ([Assumption]: not yet measured). Mitigation candidates: boundary-edge dilation proportional to lost area per simplification step; scale leaf-card normals' tangent frame; bake `min_cover` per cluster and refuse to simplify below it. Tests: area ratio ≥ 0.9 down to a pixel-size threshold.
4. **GPU wind/skinning**: bone-hierarchy skinning for **instances sharing a few simulations** (cheap CPU): per-part-instance bone weights (rigid-per-cluster), **animated cluster bounds = bounds swept over bone motion limits** (stable, no worst-case WPO padding), animation cut-off by projected size (default 0.1), shared global wind + gust volumes + character-interaction forces evaluated in compute into a bone-matrix buffer. Requires skinned meshlets (not supported today) ⇒ Phase 12 depends on Phase 17.

**Status: design only; no foliage-specific code in this change.** The only foliage-adjacent code is the measured LOD/HLOD benchmark.
